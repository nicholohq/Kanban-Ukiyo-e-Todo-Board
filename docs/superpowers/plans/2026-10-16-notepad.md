# Notepad Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third view to Ukiyo Kanban — a plain-text notepad with named tabs, autosaved to the device and the account, that can promote a two-highlight selection into a real card on the board.

**Architecture:** Notes ride the existing storage facade (new IndexedDB object store at DB v2) and the existing task API pattern (new `/api/notes` routes over a new Turso table). `todoStore` stays the single snapshot writer and saves notes with the tasks; a new `notesStore` holds note state and does its own debounced server sync, and merges local writing with the server on load instead of being replaced by it. The send-to-board flow is a docked panel inside the notepad card, not a modal, so the note stays selectable between the two highlights.

**Tech Stack:** SvelteKit 2, Svelte 5 runes (JSDoc types, no TypeScript), `idb` (IndexedDB), `svelte-dnd-action` + `svelte/animate` flip (tab drag), libSQL/Turso (`@libsql/client`), Vitest + `fake-indexeddb`.

**Spec:** `docs/superpowers/specs/2026-10-16-notepad-design.md` — read it alongside this plan. Where this plan and the spec disagree, the spec's intent wins and the discrepancy is a bug to report.

## Global Constraints

- **No new dependencies.** `idb`, `svelte-dnd-action`, `vitest`, `fake-indexeddb` are already present. Installing anything is out of scope.
- **Svelte 5 runes, JSDoc types, no TypeScript.** Follow the class-with-`$state`/`$derived` store pattern in `src/lib/stores/todoStore.svelte.js`.
- **File naming follows the existing tree, not the guide's kebab-case rule:** components are `PascalCase.svelte` (all 20 existing components), utils/stores are `camelCase.js`. The Engineering Guide §8 says kebab-case; the codebase says otherwise. Match the codebase.
- **Plain text only.** No rich text, no markdown rendering, no checkboxes inside the notepad. Line breaks are preserved and nothing is interpreted.
- **Exact copy strings** (do not paraphrase): `'Please enter a title.'` · `'A task with this title already exists.'` · `'Untitled'` · empty state `"Start a note for a subject you're studying"` · sync labels `'Saving…'` and `'Saved'`.
- **Timings:** local snapshot save debounce stays 300 ms (existing). Notes server sync debounce is 1000 ms, coalescing to one `PATCH` per changed note.
- **A note's id is generated on the client and sent to the server** (`POST /api/notes` accepts `input.id`). This deliberately differs from `/api/tasks`, which generates its own id. Merge-on-load matches notes by id, so ids must be the same on both sides; a server-generated id would resurrect the client's note as a second copy.
- **New cards land in `status: 'todo'`** and carry the note's name as a tag (`tags: [note.title]`, normalised to lower case by `addTask`).
- **Sending never removes text from the note.** Notes are excluded from header search, from `filters`, from `counts`, and from the board.
- **`notesStore` never imports `todoStore`.** `todoStore` imports `notesStore`, one way.
- **Do not touch task behaviour:** `TaskForm.svelte`, `KanbanBoard.svelte`, `KanbanColumn.svelte`, `TaskCard.svelte`, `TaskList.svelte`, `todoStore`'s existing CRUD, filters, board projections, and undo stack stay as they are.
- **Green on every task boundary:** `npm test` (29 existing tests must keep passing, plus each task's new ones) and `npm run check`.
- **Commit only the files the task lists.** Never commit `node_modules`, `.env*`, or `.superpowers/`.

## Review Focus

Five things the spec implies that no single task's happy path exercises. Each is pinned to a test or an explicit manual step in the task that owns the code.

1. **An existing v1 database upgrading to v2.** Real users already have an IndexedDB database with three stores. The upgrade must add `notes` without throwing `ConstraintError` and without losing tasks. — pinned by the `notes-storage` test in Task 2.
2. **A note arriving with a missing title or a null body.** Nothing on the wire guarantees `title`/`body` are strings. Must normalise to `'Untitled'` / `''`, never render `undefined`. — pinned by the `mergeNotes` test in Task 1.
3. **A note whose name is blank or contains characters a filesystem refuses** (`< > : " / \ | ? *`). Export must still produce a usable `.txt` name. — pinned by the `sanitizeFilename` test in Task 1.
4. **A card title that is empty or duplicates an existing task.** Must be refused with the app's existing wording, leave the panel open, and create nothing — never look like a dead button. — pinned by the `cardTitleError` test in Task 1 and a manual step in Task 7.
5. **Typing in a note and switching tabs inside the 1000 ms sync window.** Nothing may be lost and nothing may be written to the wrong note. — pinned by a manual step in Task 6; the sync deliberately tracks note *ids*, not bodies, for exactly this reason.

```js
/** @type {readonly ['board','list','notes']} */
export const VIEWS = Object.freeze(['board', 'list', 'notes']);

/**
 * Coerce a persisted/unknown view value to a valid one.
 * @param {unknown} value
 * @returns {'board'|'list'|'notes'}
 */
export function normalizeView(value) {
	return VIEWS.includes(/** @type {any} */ (value)) ? /** @type {any} */ (value) : 'board';
}
```

- [ ] **Step 4: Implement `src/lib/utils/notes.js`**

Module doc: pure helpers for the notepad — no Svelte, no storage, no network. Algorithms that the tests pin exactly:

- `normalizeNote(raw)`: `title` → `String(raw.title ?? '').trim() || 'Untitled'`; `body` → `String(raw.body ?? '')` (do **not** trim the body — leading/trailing whitespace in a note is the user's); `position`/`createdAt`/`updatedAt` → `Number.isFinite(Number(v)) ? Number(v) : 0`; `id` → `String(raw.id ?? '')`.
- `sortNotes(notes)`: `[...notes].sort((a, b) => a.position - b.position || a.createdAt - b.createdAt)`.
- `mergeNotes(localNotes, serverNotes)`: normalise both inputs; key by `id` in a `Map` seeded from the server; for each local note, keep it when absent, or keep whichever side has the greater `updatedAt` — **local wins on a tie** (state this in a comment: identical timestamps mean neither side changed, so the user's on-screen copy is kept). Return `sortNotes([...map.values()])`. Never drop a local-only note.
- `sanitizeFilename(name)`: replace `[<>:"/\\|?*\u0000-\u001f]` with a space, collapse runs of whitespace to one space, trim, and fall back to `'note'` when the result is empty.
- `noteToTxt(note)`: `String(note?.body ?? '').replace(/\r\n?/g, '\n')`.
- `cardTitleError(title, isDuplicate)`: `'Please enter a title.'` when the trimmed title is empty, else `'A task with this title already exists.'` when `isDuplicate` is true, else `null`. Comment that the strings are deliberately identical to `TaskForm.svelte`'s, and that `TaskForm` adopting this helper is out of scope.

Export the typedef as `Note` so storage and the store can `import('$lib/utils/notes.js').Note`.

## Deferred (not tasks — these need a decision first)

**1. The ❖ "already sent" mark.** Spec §9.3 is unresolved: a `<textarea>` cannot style a range. The three options are a mirrored layer behind the textarea, a "sent from this note" list in the tools row, or a literal `❖ ` character inserted into the text. The docked panel from Task 7 makes the mirrored layer newly feasible. Nothing in Tasks 1–8 marks sent text; the feature ships without it. Pick an option and it becomes a small follow-up task on top of Task 6's textarea.

**2. Shared-device caching.** Spec §9.2. Local persistence stays device-wide and not per-user. For notes this is a privacy limitation **wider than tasks**: sign-out clears nothing locally and merge-on-load keeps local notes, so on a shared device a second account sees the first account's note text **online and persistently**, whereas tasks replace local state on load and surface a previous user's rows only when offline. Accepted for this session; the fix is to scope the cached notes by user id, the per-user repository work (**Session 006's** local-first inversion — see the amendment at the foot of ADR-003).
